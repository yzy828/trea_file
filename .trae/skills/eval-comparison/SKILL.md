# 横向对比评测（eval-comparison）

把多个同类对象放进**同一套框架**里比较，找出差异化的强弱项，并给出"谁适合谁"的选型结论。前提是各对象已用同一 `eval-framework` 完成 `eval-scoring`。

## 何时调用

- 用户拿多个候选（手机 A/B/C、两款软件、几款服务）要对比选优。
- 需要"哪款更值得买""差异在哪""我该选哪个"的结论。
- 竞品分析、导购推荐场景。

## 前置条件

- 所有对象使用**同一套维度与权重**打分（尺度一致才可比）。
- 若框架不同，先用 `eval-framework` 统一后再评，否则对比无意义。

## 工作流程

### 1. 对齐对比对象

确认对比名单、价格档位/定位是否可比。跨档位对比需说明（如"旗舰 vs 中端"仅作参考）。

### 2. 生成对比矩阵

逐维度列出各对象得分与关键证据，突出差异：

```markdown
| 维度(权重) | 对象A | 对象B | 对象C | 关键差异说明 |
|-----------|-------|-------|-------|--------------|
| 性能(30%) | 9     | 7     | 8     | A 跑分领先约 15% |
```

### 3. 提炼差异化

- **各对象的独有优势**：只有它能做到的亮点。
- **各对象的明显短板**：拉低体验/性价比的缺陷。
- **同质化部分**：大家都差不多，可作为"不重要的决策因素"剔除。

### 4. 按人群给建议（重点）

对比的终极价值是"帮具体的人做选择"，避免只列分数不给结论。给每个对象标注适配人群：

```markdown
- 对象A：适合看重性能、预算充足的用户（短板：价格高、续航一般）
- 对象B：适合预算有限、追求均衡的用户（短板：无突出亮点）
- 对象C：适合看重续航与便携的用户（短板：性能一般）
```

同时给出"若只选一个"的明确推荐，并说明理由与适用前提。

## 输出模板

```markdown
## 横向对比：<品类>（对象A / B / C）

### 对比矩阵
（表）

### 差异亮点
- 独有优势 / 明显短板 / 同质化项

### 选型建议
- 对象A：适合… / 对象B：适合…
- 结论：若只选一个，推荐 <X>，理由…

### 局限
- 本次未覆盖的场景/证据不足之处
```

## 约束

- 只对比"可比"对象；跨档位、跨品类对比要显式声明。
- 结论必须有分数与证据支撑，禁止凭空"A 完胜 B"。
- 尊重各对象差异，不踩一捧一；短板如实说，亮点如实夸。
- 选型建议要落到"人群/预算/场景"，而非泛泛而谈。
