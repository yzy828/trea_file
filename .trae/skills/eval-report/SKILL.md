# 测评报告撰写（eval-report）

把 `eval-framework`、`eval-research`、`eval-scoring`、`eval-comparison` 的产出，整合成一份**读者能直接决策**的结构化测评报告。它是整条流水线的最终交付物。

## 何时调用

- 各环节已完成，需要输出成文/成稿的测评报告。
- 用户要求"写成一篇测评""出一份评测报告""整理成文章"。

## 报告结构（结论先行）

按以下顺序组织，读者可快速抓重点：

1. **摘要 / 一句话结论**：先给总分与推荐结论（BLUF，Bottom Line Up Front）。
2. **测评对象与方法**：对象信息、测评时间、维度与权重来源、证据来源等级说明。
3. **评分明细**：各维度得分表 + 给分理由（可配雷达图/柱状图说明，但需标注数据）。
4. **核心优点 / 核心缺点**：各 3~5 条，每条附证据。
5. **横向对比与选型建议**（如有）：复用 `eval-comparison` 产出。
6. **适用人群与购买/选择建议**：明确"适合谁、不适合谁"。
7. **局限与证据不足**：诚实标注没测到/证据不足的部分，避免误导。
8. **附录：数据与来源**：完整证据库链接、参数表、参考来源。

## 写作规范

- **结论先行**：每段先给判断，再给依据，不绕弯。
- **客观/主观分离**：客观数据与主观体验分开写，主观部分标注"主观感受"。
- **可溯源**：关键结论附来源链接与时间，读者能自行核实。
- **克制措辞**：不用"天花板/无敌/最强"等绝对化营销词；用"在 X 场景下优于 Y"这种有边界的表述。
- **给边界**：写明结论的适用前提（预算、场景、时间窗口）。
- **诚实标注**：证据不足就写"未充分验证"，不硬凑结论。

## 输出模板

```markdown
# <对象名> 测评报告

## 摘要
总分：X.X/10｜结论：<一句话推荐/不推荐及理由>

## 测评方法
- 对象 / 时间 / 维度与权重 / 证据来源等级

## 评分明细
| 维度 | 得分 | 置信度 | 给分理由 |
（表 + 可视化）

## 优点 / 缺点
- 优点1（证据）…

## 选型建议（可选）
（横向对比与推荐）

## 适用人群
适合… / 不适合…

## 局限
未覆盖 / 证据不足项

## 附录
来源链接与数据
```

## 约束

- 报告是"数据驱动结论"，不是观点堆砌；每个结论都要能指回证据库。
- 不编造来源、不夸大、不隐瞒短板。
- 需要可视化图表时，可用 Inline Visuals（如雷达图、对比表）增强可读性，但数据必须来自评分结果。
