# 测评框架设计（eval-framework）

为任意测评对象（硬件、消费品、软件、服务、内容等）设计一套**可复用、可量化、可交叉验证**的多维测评框架。它是整条测评流水线的第一步，产出物会被 `eval-research`、`eval-scoring`、`eval-comparison` 直接复用。

## 何时调用

- 用户提出要"测评/评测/打分/评价"某个事物，但还没有明确的评估维度与标准。
- 需要把一次主观感受转化为一套结构化、可复现的评分体系。
- 需要为多个同类对象做横向对比，必须先统一框架（配合 `eval-comparison`）。

## 目标

产出一张「测评框架表」，包含：维度、子维度、权重、评分标准（rubric）、证据要求、数据来源。

## 工作流程

### 1. 明确测评对象与受众

先问清（信息缺失时用 AskUserQuestion 补齐）：

- **测评对象**：是什么品类/具体型号/具体服务？目标场景是什么？
- **受众与用途**：给谁看？是导购决策、竞品分析、还是质量验收？
- **对比基准**：是否有明确竞品或预算区间？
- **时效性**：测评结论的有效时间窗口（科技产品迭代快，需标注时间）。

### 2. 拆解维度（多维度）

按通用维度库拆解，再结合对象特性增删。默认维度库：

| 维度 | 适用说明 |
|------|----------|
| 性能/效果 | 核心功能的客观表现（跑分、速度、准确率、产出质量） |
| 体验/易用性 | 上手成本、操作流畅度、学习曲线、交互合理性 |
| 质量/可靠性 | 耐用度、稳定性、故障率、品控一致性 |
| 价格/性价比 | 价格绝对值、同档位竞争力、长期持有成本 |
| 设计/外观 | 工业设计、材质、颜值、人机工程 |
| 服务/售后 | 客服响应、售后政策、保修、退换货、生态支持 |
| 口碑/声誉 | 真实用户长期口碑、品牌信誉、社区评价 |
| 创新/差异化 | 相对竞品的独有亮点、技术突破 |

每个一级维度下可再拆 2~4 个**可观测**的子维度（子维度必须能被证据支撑，避免空泛）。

### 3. 分配权重

权重需体现"对目标受众的重要性"，而非平均分配。常用方法：

- **受众关注度赋权（推荐）**：按目标用户最关心的点排序赋权。例：导购场景下"性价比"和"体验"往往高于"创新"。
- **AHP/两两比较**：维度两两比较重要性，算出权重（适合高严谨度场景）。
- **等权+备注**：信息不足时先等权，并在报告中注明权重假设。

所有维度权重之和必须等于 100%（或 1.0）。

### 4. 定义评分标准（rubric）

每个维度给出一致的分级锚点，避免打分随情绪漂移。推荐 1~10 分制，配合锚点描述：

- 8~10 优秀：明显优于同类主流，可量化领先
- 6~7 良好：达到主流水平，局部亮点
- 4~5 一般：可用但无明显优势，存在妥协
- 1~3 差：明显短板或缺陷

**区分两类指标**：
- **客观指标**：有数据可依（参数、跑分、价格、故障率），打分需引用具体数值。
- **主观指标**：体验类，需多方证据交叉（多来源真实用户评价），并标注主观性。

### 5. 定义证据要求

每个维度写明"要打这个分需要什么证据"，例如：

- 性能 → 官方参数 + 至少 2 个独立实测来源
- 口碑 → 电商真实评价 + 论坛/社区 + 权威媒体，注意区分水军
- 售后 → 官方政策页 + 真实用户售后案例

## 产出模板

```markdown
## 测评框架：<对象名>
- 受众/用途：
- 测评时间：

| 维度 | 子维度 | 权重 | 评分标准(1-10) | 证据要求 | 数据来源 |
|------|--------|------|----------------|----------|----------|
| ...  | ...    | ...  | ...            | ...      | ...      |
```

## 约束

- 框架必须**先于采集和打分**确定，测评中途不随意改权重（否则结果不可复现）。
- 维度不求多，求"能落到证据上"。无法验证的维度宁可不设。
- 产出后交给 `eval-research` 去采集证据，或直接进入 `eval-scoring`。
